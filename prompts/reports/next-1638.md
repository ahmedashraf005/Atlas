# Next.js 16.3.8 upgrade report

## Result

Part 1 is complete on `next-1638`: Next.js moved from **16.3.6** to **16.3.8**, with no directly pinned `@next/*` dependency. Part 2 was reverted as instructed after its new browser test failed. No commit was made.

## September 30 advisory applicability

The conditions below come from the [official Next.js security release](https://nextjs.org/blog/september-2026-security-release); the evidence is from Atlas's routes and `next.config.ts`.

| Advisory | Applicable to Atlas? | Evidence |
| --- | --- | --- |
| Image optimizer SSRF through `images.remotePatterns` | No | No `images.remotePatterns` configuration or remote image optimization. |
| Pages Router SSG/ISR cache poisoning | No | No Pages Router directory; Atlas uses App Router and deploys on Vercel. |
| Root catch-all plus SSG/ISR cache poisoning | No | No root catch-all route; sandbox pages render dynamically. |
| Webpack metadata image route `dynamicParams` bypass | No | No dynamic metadata image route or `dynamicParams`/`generateStaticParams`; production builds use Turbopack. The icon is a static SVG. |
| Nested `'use cache'` with root params | No | No `'use cache'` usage and Cache Components are not enabled. |
| Draft Mode content leaking through pending cache fill | No | No Draft Mode or Cache Components usage. |
| `next dev` MCP information disclosure | Yes, local development only | `pnpm dev` and the E2E development fixture run `next dev`; Vercel production does not. The upgrade patches the local development endpoint. |

The release notes also state that a **critical** fix and another **high-severity** fix were postponed due to upstream dependency delays. They are not claimed as fixed by 16.3.8; the critical fix is pending upstream and will be applied when released. The clean audit below does not change that status.

`agentRules: false` is supported by the installed Next 16.3.8 types and now prevents `next dev` from appending generated guidance to `AGENTS.md`. The clock E2E test now subtracts elapsed wall time before checking the exact sandbox jump; the displayed timestamp is only precise to a minute.

## Changed paths

- `next.config.ts` — disabled Next's automatic agent-rule append.
- `package.json` — pinned Next 16.3.8.
- `pnpm-lock.yaml` — locked Next and its matching bundled packages.
- `pnpm-workspace.yaml` — retained pnpm's automatic version-specific release-age exclusions for the fresh release.
- `tests/e2e/demo-controls.spec.ts` — made the clock jump assertion account for wall time and minute-rounded display.
- `prompts/reports/next-1638.md` — recorded verification, advisory applicability and the reverted layout attempt.

## Layout follow-up

The fair-value figure, persona-select truncation and document-row stacking remain as on `main`. The attempted Part 2 changes were reverted because the select value still computed `text-overflow: clip` in Chromium; no unverified layout change was retained.
